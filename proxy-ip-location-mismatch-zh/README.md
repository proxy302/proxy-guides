# 代理 IP 查到的国家或城市和买的不一样，怎么办？

先分清是城市不一样，还是国家不一样。城市对不上很常见，一般不算出错：IP 的位置是各家定位库推算出来的，同一个地址在三家库里可能是三个城市。国家对不上才需要处理。先确认你查的确实是代理的出口，再用两三家定位库交叉查：多数库给出的国家和你买的一致，说明是个别库判错了，把那一家的结果交给卖家处理即可；多数库都不一致，把 IP 和各家的查询结果一起发给卖家客服。

*本文由 Proxy302 维护，我们出售这类代理 IP。文中的查询命令和脚本 2026 年 11 月实际跑过；各定位库的更正渠道按它们官网当时的页面核对。*

## 第一步：确认查的是代理出口，不是你自己的网络

很多「IP 不对」其实是代理根本没生效，查到的是自己的宽带地址。让查询经过代理：

```bash
curl -s -x "http://USER:PASS@HOST:PORT" https://ipinfo.io/json
```

如果买的是 SOCKS5 类型，地址开头写 `socks5h://`。返回的 `ip` 应该和订单页上的 IP 一致。指纹浏览器、手机里用的话，就在那个环境里打开同一个网址看。显示的是你自己的地址，先去解决「代理没生效」，不用往下看了。

## 第二步：多查几家定位库

把下面的脚本存成 `geo_compare.py`（只用 Python 自带的库），后面跟上要查的 IP：

```python
import json
import sys
import urllib.request

# 三家定位库的免费查询接口，都有次数限制，偶尔查查够用
SOURCES = {
    "ipinfo":      ("https://ipinfo.io/{ip}/json",          "country", "city"),
    "IP2Location": ("https://api.ip2location.io/?ip={ip}",  "country_code", "city_name"),
    "ipapi":       ("https://ipapi.co/{ip}/json/",          "country_code", "city"),
}

ip = sys.argv[1]
for name, (url, country_key, city_key) in SOURCES.items():
    try:
        req = urllib.request.Request(url.format(ip=ip), headers={"User-Agent": "geo-compare"})
        with urllib.request.urlopen(req, timeout=15) as resp:
            data = json.load(resp)
        print(f"{name:12} 国家={data.get(country_key)}  城市={data.get(city_key)}")
    except Exception as e:
        print(f"{name:12} 查询失败：{e}")
```

```bash
python3 geo_compare.py 你的代理IP
```

我们拿公共 DNS 地址 1.1.1.1 试的时候，三家给的国家相同，城市就有一家不一样。这正是定位库的常态。

## 第三步：按结果判断

| 查询结果 | 说明 | 怎么办 |
|---|---|---|
| 国家都对，城市各不相同 | 定位库对城市的推算本来就粗 | 一般不用处理，绝大多数用途看国家 |
| 多数库国家对，个别库不对 | 那一家的数据旧了或判错了 | 把那一家的查询结果截图发给卖家；你要用的网站恰好用那一家时，这一点才要紧 |
| 多数库国家都不对 | 这个 IP 的定位和你买的不符 | 把 IP 和三家的结果发给卖家客服，按卖家的规则处理 |
| 查到的是你自己的地址 | 代理没生效 | 回到第一步 |

## 为什么各家定位库会不一样

定位库不是直接「看到」一个 IP 在哪，而是根据地址段的登记信息、网络运营方提供的资料等来推算，各家的数据来源和更新频率不同。IP2Location 在自己的准确率说明页上就写到：地址段经常被重新分配，用过期的数据库准确率会逐月下降，移动网络的定位也比固定宽带难。所以同一个 IP，换一家库、隔一段时间，结果都可能变。

你常用的某个网站显示「你在某地」，只说明那个网站用的定位库这样判断。大多数网站不公开自己用哪一家。

## 定位库能不能改

能申请，但不保证改，而且由地址段的所有者（网络运营方）提交的申请最有分量：

- **MaxMind**：有公开的[更正表单](https://www.maxmind.com/en/geoip-location-correction)，登录后填 IP 或地址段、国家和邮箱。页面写明会人工核对，不保证接受。
- **ipinfo**：有[更正页面](https://ipinfo.io/corrections)。
- **IP2Location**：要求申请人证明自己有权代表这些 IP，流程比较正式。

作为代理的使用者，最省事的做法是把「哪个 IP、哪家库、显示成了哪里」整理好交给卖家，由卖家去跟进。

## 发给客服时带上这些

1. IP 地址（不要发密码）。
2. 两三家定位库的查询结果截图，或上面脚本的输出。
3. 你要用的网站上显示的位置，以及它对你的影响。

## 常见问题

**城市不对，会影响账号吗？** 定位库本身就做不到城市级都准，各家互相也对不上。对要长期登录的账号来说，一个账号一直用同一个 IP，比追求每家库的城市都一致更实际。

**静态 IP 用着用着，定位变了？** 定位库会更新，同一个 IP 的结果可能跟着变。地址本身没变，只是库的判断变了。

**动态住宅每次查城市都不一样？** 正常。动态线路会换出口，城市跟着变。需要一小段时间内固定出口，用服务商文档里的会话参数（Proxy302 的控制台会帮你生成）。

**怎么判断 IP 是住宅还是机房？** 这是另一个问题，看 ASN 和登记的组织，见[怎么判断一个 IP 是住宅、ISP 还是机房](../residential-or-datacenter-ip-check-zh/README.md)。
