# 代理 IP 很慢，怎么判断慢在哪一段？

用 curl 的计时输出，把一次经代理的请求拆成四段：连上代理用了多久（`time_connect`），代理打通到网站的隧道、再加上和网站的 TLS 握手用了多久（`time_appconnect`），网站多久回了第一个字节（`time_starttransfer`），全部下载完一共多久（`time_total`）。哪一段占得最多，慢就慢在哪里：第一段长，是你到代理这一程的问题；第二段长，是代理到网站这一程；第三段长，是网站自己处理得慢；最后一段长，是内容太大或带宽不够。再拿同一个请求不走代理测一遍做对照，就知道代理实际多花了多少时间。

*本文由 Proxy302 维护，我们出售这类代理 IP。下面的命令和脚本 2026 年 11 月在 curl 8.7 上，经本机的 HTTP 和 SOCKS5 测试代理跑过。文中不给「正常应该多少秒」的数字，因为它取决于你在哪、代理在哪、网站在哪。*

## 一条命令看四段时间

```bash
curl -sS -o /dev/null -x "http://USER:PASS@HOST:PORT" \
  -w "代理状态=%{http_connect} 网站状态=%{http_code}\n连上代理=%{time_connect}s\n隧道+TLS完成=%{time_appconnect}s\n收到首字节=%{time_starttransfer}s\n全部完成=%{time_total}s\n下载字节=%{size_download}\n" \
  https://www.example.com/
```

SOCKS5 类型的 IP 把 `http://` 换成 `socks5h://`。Windows 10、11 自带 curl，在 PowerShell 里要写成 `curl.exe`，并把 `-o /dev/null` 换成 `-o NUL`。

四个时间都是从开始算起的累计值，所以要看相邻两项的差：

| 这一段 | 怎么算 | 长了说明什么 |
|---|---|---|
| 你 → 代理 | 连上代理 | 本机网络差，或者代理服务器离你远 |
| 代理 → 网站，加 TLS 握手 | 隧道+TLS完成 − 连上代理 | 代理出口离网站远，或者这一程的线路慢 |
| 网站处理 | 收到首字节 − 隧道+TLS完成 | 网站自己慢，和代理关系不大 |
| 传输内容 | 全部完成 − 收到首字节 | 内容大，或带宽不够 |

访问 `http://` 开头的网站时不建隧道、也没有 TLS 握手，「代理状态」显示 000，「隧道+TLS完成」显示 0，看前后两项即可。

## 多测几次，再和直连对比

单次结果有偶然性。把下面的脚本存成 `timing.sh`，连测几次：

```sh
#!/bin/sh
# 用法：sh timing.sh "http://USER:PASS@HOST:PORT" 5
# 第一个参数写 direct 表示不走代理
PROXY="$1"; N="${2:-5}"; URL="https://www.example.com/"
i=1
while [ "$i" -le "$N" ]; do
  if [ "$PROXY" = "direct" ]; then set -- ; else set -- -x "$PROXY"; fi
  curl -sS -o /dev/null --max-time 30 "$@" \
    -w "第${i}次 连代理=%{time_connect}s 隧道+TLS=%{time_appconnect}s 首字节=%{time_starttransfer}s 总计=%{time_total}s 状态=%{http_code}\n" \
    "$URL"
  i=$((i+1))
done
```

```bash
sh timing.sh "http://USER:PASS@HOST:PORT" 5
sh timing.sh direct 5
```

把 `URL` 换成你实际要访问的网站，结论才有意义。直连这一组里「连代理」那一列显示的是连网站的时间，用来对照。

## 按结果对症处理

**你 → 代理这一段长。** 先排除本机：换个网络（比如手机热点）再测。公司网络、远距离的跨境线路，都会让这一段变长。

**代理 → 网站这一段长。** 出口所在国家和网站服务器离得越远，这一段越长。访问哪个国家的网站，就优先用那个国家的 IP，这也是绝大多数人买 IP 时本来就会选的。

**网站处理这一段长。** 直连也一样慢的话，是网站自己的问题，换代理不会变快。

**传输这一段长。** 页面或文件本身大。写程序抓数据时，可以只请求需要的接口、不下载图片和视频；按流量计费的动态住宅，这样还能省钱，见 [How do I cut bandwidth when scraping through residential proxies?](../proxy-for-web-scraping-bandwidth/README.md)（英文）。

**偶尔一次特别慢，其余正常。** 看多次结果里居中的那个值，不要只看最慢的一次。

## 程序里怎么少花这部分时间

每新建一条连接，都要重新走一遍「连代理、打隧道、TLS 握手」。程序里复用连接（例如 Python 用 `requests.Session()`，其他语言打开 keep-alive），后面的请求就能省掉这几步。

要注意的是：在动态住宅线路上复用连接，出口 IP 会一直是同一个。需要每次换出口，就要新建连接，多出来的握手时间是换 IP 的代价。需要在一小段流程里固定出口，用服务商文档里的会话参数（Proxy302 的控制台会帮你生成）。

## 常见问题

**HTTP 和 SOCKS5 哪个快？** 两种协议本身的开销都很小，测出来差别大的话，多半是线路不同，不是协议的原因。用上面的脚本各测几次就清楚了。

**浏览器、指纹浏览器里打开网页慢，也能这样查吗？** 可以。先用 curl 测同一个网站，curl 快而浏览器慢，问题多半在浏览器那边：页面资源多、扩展多，或者叠了第二层代理。

**测出来代理那一段很慢，怎么办？** 把脚本的输出（密码打码）发给服务商客服，比只说「很慢」有用得多。
