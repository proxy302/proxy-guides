# Kaufland 德国站卖家，Seller Portal 用什么 IP 登录？

经营主体在德国的卖家，给每个 Kaufland 卖家账号配一个德国静态 ISP（静态住宅）IP，长期不换，只在打开 Seller Portal 的那个浏览器配置里使用；同事通过 Seller Portal 的「Users & Rights」各开各的账号，用自己的邮箱登录。只是去 kaufland.de 前台看排名和同行价格，用动态住宅按流量买就够。本指南由 Proxy302 维护，我们也销售这些代理：德国静态 ISP 1 天 0.5 美元、30 天 7.99 美元，所有国家同价，30 天及以上的静态 IP 由买家独享。能不能入驻、要交哪些资料、审核怎么走，以 Kaufland 的卖家规则为准，IP 不改变这些，也代替不了审核。

## 固定 IP 解决的是什么问题

Seller Portal 不关心你用几台电脑，但每次登录的网络都会留下记录。仓库一个宽带、办公室一个、运营在家一个、老板出差用酒店网络，账号这边看到的就是一串不同的地址。把后台工作收拢到一个固定德国 IP 的浏览器配置里，出口就只有一个；谁做了哪项操作，交给 Seller Portal 的用户和权限去区分。

国家怎么定：跟公司实际经营的国家走。公司在德国，用德国 IP；公司在别的国家，就用那个国家的 IP。不要为了显得像德国本地卖家去挑德国 IP。

Kaufland 也提醒只把访问权给选定的人，并使用强密码。配好以后，固定 IP 管网络这一层，Users & Rights 管人这一层。

## 配置步骤

1. **一个卖家账号买一个德国静态 ISP。** 协议下单时定好，一个 IP 只有一种：浏览器扩展、系统代理选 HTTP；放进指纹浏览器环境多选 SOCKS5。
2. **给这个账号建一个专用浏览器配置。** Chrome、Edge 的个人资料或指纹浏览器的环境都行，只用来开这个账号的 Seller Portal。
3. **填代理：** 主机、端口、用户名、密码照订单页填，协议一致。
4. **登录前确认出口。** 在这个配置里打开 `https://ipinfo.io/json`，`country` 应为 `DE`。终端里：

   ```bash
   curl -sS --max-time 20 -x "http://USER:PASS@HOST:PORT" https://ipinfo.io/json
   ```

   USER、PASS、HOST、PORT 是占位符；SOCKS5 的 IP 用 `socks5h://`。
5. **账号持有人登录，再在「Users & Rights」里邀请同事。** 同事收邮件注册后，同样在这个浏览器配置里登录。
6. **按 IP 打开自动续费。** 到期不续，IP 会被释放，重新购买拿到的是另一个地址。
7. **记台账：** 卖家账号、IP、浏览器配置名、每个用户的权限、续费日期。

## 平台要求核验时

照入驻时提交的公司登记、负责人和收款信息如实回复。代理只管网络出口，和核验无关，也帮不了资料不真实的申请。账号受限时，通过 Kaufland 的官方渠道沟通处理。

## 出问题先看这里

| 现象 | 可能原因 | 处理 |
|---|---|---|
| ipinfo 显示的不是 DE | 浏览器配置没走代理，或叠了其他全局网络工具 | 只留一层代理，重新检查设置 |
| 代理检测失败 | 协议填反（HTTP、SOCKS5） | 按订单页的协议改 |
| 407 或一直弹认证框 | 代理用户名、密码错 | 从订单页重新复制 |
| 同事登录老是被要求额外确认 | 有人不在这个配置里登录 | 约定后台只在这个配置里打开 |
| 之前能用，今天连不上 | IP 到期被释放 | 提前续费或开自动续费 |

## 常见问题

**同一个账号，几个同事能同时用这个 IP 吗？** 可以。他们是同一家店的不同用户，在同一个浏览器配置里各用各的登录，出口是一个 IP。

**德国哪个城市好？** 城市不是关键，国家对就行。购买页能选城市时，挑公司或仓库附近的，选了就固定下来。

**能不能拿 1 天的 IP 先登录试试？** 可以先用 1 天的 IP 把配置、检测流程走通；正式长期登录用 30 天或更长的，并打开自动续费。

**有免费试用吗？** 没有。最小购买是 1 个静态 IP 用 1 天，0.5 美元。
